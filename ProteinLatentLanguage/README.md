# Protein Latent Language tokenizer

PLL converts frozen ESM-2 150M residue representations into a 4,096-state contextual vocabulary. It keeps one content token per residue. The selected Stage 2 checkpoint decodes fixed quantized vectors through a 12-layer transformer and a linear 21-class residue head, including the X class.

## Environment

Install a CUDA-enabled PyTorch build appropriate for your system, then install the Python dependencies:

```bash
cd ProteinLatentLanguage
python -m pip install -r requirements.txt
```

The dependencies follow the archived project. They are not an exact lockfile of the original training environment. The supplied configurations use bitsandbytes 8-bit Adam and bf16. The `esm` package is imported by the historical encoder module even though the paper uses Hugging Face ESM-2, rather than ESMC.

## Train Stage 1

[Stage 1 config](configs/stage1/config.yaml) and its adjacent [quantizer config](configs/stage1/learnable.yaml) come from `results/final/2025-10-21__16-31-28`.

Supply UniRef50 training, validation, and test CSVs with an `Amino Acid Sequence` column. The historical loader prepares all three splits. Update `train_settings.data_path`, `valid_settings.data_path`, and `test_settings.data_path`, then run:

```bash
accelerate launch --num_processes 1 train.py --config_path configs/stage1/config.yaml
```

Use `accelerate launch --multi_gpu --num_processes N` for distributed training. The saved `batch_size` is per process. Changing the number of GPUs changes the global batch unless you adjust accumulation. The original config trains for 64 epochs with up to two million training sequences, a frozen ESM-2 encoder, and stochastic code sampling.

The run directory contains `config.yaml`, `learnable.yaml`, training logs, and checkpoints. Keep these files together.

## Train Stage 2

[Stage 2 config](configs/stage2/config.yaml) and [quantizer config](configs/stage2/learnable.yaml) come from `results/final/stage_2/2025-10-24__21-30-50`.

Set `resume.resume_path` to the Stage 1 `checkpoints/best_valid.pth` you just trained. Stage 2 freezes the latent encoder and codebook, discards Stage 1 decoder weights, and trains a reinitialized transformer decoder with a linear residue-classification head. Stochastic code sampling is disabled. The saved training configuration uses eight epochs and up to twenty million training sequences.

```bash
accelerate launch --num_processes 1 train.py --config_path configs/stage2/config.yaml
```

The stages deliberately have different `learnable.yaml` settings. This release loads that file from beside the selected stage configuration rather than a shared global file.

## Encode sequences

Set `trained_model_dir` in [encode.yaml](configs/inference/encode.yaml) to a saved Stage 2 run. Its `checkpoint_path` is relative to that run directory. Set `data_path` to a CSV containing protein sequences.

```bash
python inference_encode.py --config_path configs/inference/encode.yaml
```

The encoder writes space-separated integer code indices in a `vq_indices.csv` output. These are content codes, not language-model BOS/EOS or condition tokens.

## Decode PLL tokens

Set the saved Stage 2 run and the input CSV in [decode.yaml](configs/inference/decode.yaml):

```bash
python inference_decode.py --config_path configs/inference/decode.yaml
```

The input requires an `indices` column containing whitespace-separated integers. Optional `sequence` and `sequence_length` columns preserve reference sequences and lengths. Content codes are integers from 0 to 4095. Padding is -1 and is masked before decoding. Output is written to `decoded_sequences.csv`.

To decode samples generated by PLLM, first convert its `pll_sequence` output column:

```bash
python ../ProteinLanguageModel/prepare_pll_decode_input.py --input path/to/generated_sequences.csv --output data/pll_generated_tokens.csv
python inference_decode.py --config_path configs/inference/decode.yaml
```

ESM-2 is used to construct PLL targets from observed sequences. PLLM sampling and PLL residue decoding do not require an ESM-2 forward pass. The historical model constructor can still instantiate the frozen encoder when loading a full checkpoint.
